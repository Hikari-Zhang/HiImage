## 判断规则

- P0：当前必须停止使用的故障。本次在本机、单用户部署范围内未确认 P0；这不是完整安全审计结论。
- P1：已有功能的数据、资源或任务正确性问题，应先修复。
- P2：近期兼容性、体验与效果改进；按下表顺序推进。
- P3：需要测量收益后再推进的架构优化。
- “已复现”指此前受控模拟已触发问题；“代码确认”指实现存在对应缺口，尚未对真实模型执行破坏性或网络故障测试；“待测”不得当成已证明的性能瓶颈。

模型条目会共享权重仓库，模型 ID 不等于独立磁盘资源。文件存在、下载完成、运行时可加载也不是同一状态。这两个边界是本轮模型管理优化的核心。

## 优先级与执行顺序

同一优先级按序号执行。每项先补可失败的回归用例，再修改并执行针对性测试；通过后进入下一项。真实模型冒烟测试应使用已有本地权重，删除和竞争测试使用临时缓存与受控下载器。

| 顺序 | 优先级 / 编号 | 判断与修改范围 | 必须通过的验收 |
| --- | --- | --- | --- |
| 1 | P1 / MODEL-SAFE-01 | **模型文件删除保护，代码确认。** 当前按模型条目直接删除 HF 仓库，缺少共享引用、下载和运行占用检查。先建立最小资源引用映射与删除互斥，无需等待完整运行实例管理重构。 | 两个条目共享仓库时默认拒绝破坏共享资源，并列出影响；下载或推理占用时拒绝删除；独占闲置资源可删除并立即刷新检查缓存。仅使用临时文件验证。 |
| 2 | P1 / DL-01 | **取消与重试竞态，已复现。** 取消立即释放槽位，但底层线程未必结束；旧任务收尾可能移除同 ID 新任务。引入每次下载的独立标识、实际退出后释放槽位、按所有权收尾，并避免同资源并发写入。 | 最大并发为 1 时取消后重试，真实工作线程不超过 1；旧事件不覆盖新任务；旧任务不能删除新任务槽位或关闭其订阅。 |
| 3 | P1 / DL-02 | **下载终态丢失，已复现。** SSE 初次订阅跳过历史终态，启动失败分支不广播。连接时发送当前完整快照，统一成功、失败、取消收尾；提示去重在前端完成。 | 下载先完成后订阅仍立即收到终态；启动失败和重连均能恢复正确状态；同一次完成只提示一次。 |
| 4 | P1 / INFER-01 | **CLI 超时失效，已复现。** 主线程阻塞读 stdout，可能无法进入带超时的 wait；静默子进程会长期占用推理槽位。使用独立日志读取与总截止时间，统一超时回收。 | 无日志且不退出的受控子进程在截止时间附近终止；有持续日志也不突破总超时；异常后下一项推理可执行，无残留子进程。 |
| 5 | P1 / DL-03 | **依赖下载阻塞异步服务，代码确认。** 协程内直接调用同步 snapshot_download，依赖失败还会继续。依赖与主下载统一进入工作线程、取消和错误传播流程。 | 用阻塞假下载器验证健康查询、SSE 心跳仍可响应；必需依赖失败时主下载不启动，任务准确失败并释放槽位。 |
| 6 | P2 / IOPAINT-EXIT-01 | **彻底移除 IOPaint，架构迁移。** 直接模型推理替代 CLI 与本地 HTTP 服务，保留快速修复并验证生成式修复；清理执行器、模型注册、服务生命周期、安装覆盖和容器依赖。详见下方分阶段计划。 | 干净环境不安装 IOPaint，pip check 通过；保留功能和下架范围明确；各替代路径真实模型验收通过；运行代码、安装脚本和部署配置无 IOPaint 依赖，历史记录可保留。 |
| 7 | P2 / MODEL-PATH-01 | **统一模型目录，确认需要修改。** 当前未完整遵循 HF_HUB_CACHE、XDG_CACHE_HOME；不同框架与检查器可能指向不同位置。遵循安装版本的原生缓存规则，启动前初始化默认值，优先显式传入目录，避免请求期间修改父进程环境。 | 默认路径、仅 HF_HUB_CACHE、仅 XDG_CACHE_HOME、配置冲突优先级、子进程和容器路径一致性均覆盖；已有缓存可离线复用；不自动移动或删除旧权重。详细范围见[原清单](SYSTEM_ARCHITECTURE.md#193-待修改统一模型目录解析与环境变量设置)。 |
| 8 | P2 / MODEL-STATE-01 | **拆分模型状态，代码确认。** IOPaint CLI 当前直接判为 OK，不能代表已有权重或可离线运行。分别表达文件检查、下载任务、运行实例状态，修正首次使用下载的文案。 | 缺失 CLI 权重不能显示已下载；损坏缓存、下载完成但加载失败、正在加载或占用均可区分；查询状态本身不触发下载。 |
| 9 | P2 / UI-01 | **修复无效画布工具，代码确认。** 去水印页面平移按钮的状态未传入画布；魔棒按钮缺少对应处理。先接通平移；魔棒实现前移除或禁用并说明。 | 浏览器验证按钮平移、空格平移、画笔和橡皮切换正确；无可点击但无行为的工具；导出遮罩保持正确。 |
| 10 | P2 / ENV-01 | **本地与容器推理依赖一致，代码确认。** transformers、huggingface_hub 等版本存在差异。统一受支持的版本来源，CPU/GPU 镜像按兼容性分别验证。 | 干净环境安装、依赖一致性检查、关键模块导入、已有权重加载均通过；GPU 镜像还需一次实际推理。未运行 Docker 的检查不能宣称镜像验收通过。 |
| 11 | P2 / QUALITY-01 | **建立去水印质量基准，确认需要。** 当前合成图、少量复杂图不足以证明真实效果。建立含半透明、重复、倾斜、图标和无水印负样本的固定集，建议至少 30 张，保留人工标注和可用的无水印原图。 | 记录检测召回与误检、残留、区域外像素差、结构保真、耗时和内存；提供固定样例的前后对比。先测基线，再确定改进目标，不能以候选框变多替代效果提升。 |
| 12 | P2 / GEN-01 | **新增局部生成式修复模式，新增功能。** 保留现有 LaMa 快速修复，在同一去水印页面共用原图和遮罩，后端独立执行器。先用手动遮罩做 A/B 验证，隔离检测误差；核对 Flux Fill 的专用管线和真实设备兼容性。 | 在 QUALITY-01 固定集上对比 LaMa，记录提示词、参数、耗时和峰值显存；遮罩外像素保持原图，关键人脸和文字结构人工复核；确认实际收益后再接完整 UI，不直接替换原模式。 |
| 13 | P2 / FE-SYNC-01 | **减少模型列表重复刷新，代码确认。** ModelManager 按任意 store 变更检查是否存在完成项，容易反复刷新；多个 hook 实例各自同步。改为按任务状态转换失效缓存，统一请求去重，订阅同时绑定后端地址和任务实例。 | 高频进度不重复拉模型列表；同一完成事件只失效一次；切换后端不复用旧服务的连接与状态。 |
| 14 | P2 / CI-01 | **固化回归检查，工程保障。** 将已有后端、前端、类型与构建检查纳入 CI；真实模型端到端检查作为需要权重的独立任务，不要求普通 CI 下载大模型。 | 普通 CI 无模型和 GPU 时可运行核心检查；真实模型检查明确显示执行或跳过原因；上述故障回归持续运行。 |
| 15 | P3 / RUNTIME-01 | **模型复用与设备策略，待测。** 当前 session 收尾卸载、IOPaint server 被停止、多区域 CLI 重复加载，存在冷启动成本。先测加载耗时和峰值内存，再实施单实例复用、闲置回收及显存预算；CPU 强制策略按模型和设备验证后调整。 | 连续同模型请求实测收益；切换模型、OOM、异常和关闭能释放资源；不得未经兼容性测试直接移除 CPU 回退。依赖 MODEL-SAFE-01、DL-01、MODEL-PATH-01、MODEL-STATE-01，并在移除 IOPaint 后评估新执行器。 |

## IOPAINT-EXIT-01：彻底移除 IOPaint

新增日期：2026-11-02。优先级 **P2，P1 通用可靠性修复之后、其余 P2 大范围改造之前**。状态：待处理。本项登记不表示已卸载依赖、移除模型或开始迁移；下一项以顶部进度表为准。

目标是由项目直接管理所需模型的推理，最终不安装、不调用、不启动 IOPaint。双虚拟环境仅可作为临时迁移措施，不作为最终架构。移除框架与提升模型质量分别验收，不能把“去掉 IOPaint”记作复杂水印效果已经改善。

| 阶段 | 待修改内容 | 进入下一阶段前的测试 |
| --- | --- | --- |
| A：盘点与基线 | 枚举去水印、换装、合成等全部调用，记录 CLI、HTTP、模型条目、配置、环境变量、安装和 Docker 依赖；确定保留、替代和下架能力。先用现有可运行路径保存固定图片、遮罩、参数和结果。 | 每个入口都有迁移去向；基线可重复运行；记录实际设备、耗时、内存与失败情况。无可用基线的条目明确标注，不推定兼容。 |
| B：直接快速修复 | 用经过验证的 PyTorch 或 ONNX 实现直接运行 LaMa，复用现有遮罩、局部裁剪、合成和对比逻辑，验证权重格式和设备兼容。 | 固定样例质量与耗时对比；遮罩外像素一致；空遮罩、多区域、异常、取消及资源释放回归；至少一次真实模型端到端下载结果。 |
| C：直接生成式修复 | 基于现有执行器接入专用填充管线，先验证 Flux Fill 等候选，手动遮罩隔离检测误差；确认真实显存、耗时和保真后再接 UI。迁移其他保留的合成功能或明确下架。 | 固定种子和参数的 A/B 对比、结构人工复核、区域外像素一致、OOM 和失败回收；保留能力逐项跑通，不以注册成功代替实际推理。 |
| D：完整清理 | 移除 IOPaint 执行器、CLI/HTTP 调用、服务进程及配置，清理专用缓存桥接、合成 snapshot 和占位元数据写入；更新模型注册和前端入口、测试、文档、Docker 与安装脚本。旧用户权重保留，不自动删目录。 | 静态扫描确认生产代码及安装部署无活动依赖；无失效配置和可选但无法运行的旧模型；验证已有缓存复用以及共享删除保护。历史说明、迁移文档和禁止回归的测试可包含 IOPaint 字样。 |
| E：干净环境验收 | 各支持平台/设备使用一致的受支持依赖来源安装，移除专为 IOPaint 先装旧版再强制覆盖的步骤；安装与启动职责分开，分别记录环境指纹。 | 新环境不含 IOPaint，依赖检查、导入、后端与前端回归通过；CPU/GPU 及容器按支持矩阵实际验证；重复正常启动不安装或改写依赖。未执行项保持待验证。 |

每个阶段使用“待处理 → 进行中 → 待验证 → 已完成”记录实际测试依据；全部阶段通过才将 IOPAINT-EXIT-01 标记完成。暂未开始任何阶段。

与原清单的关系：

- **INFER-01**：在旧 CLI 仍可使用期间保留原优先级和超时修复要求；若迁移先覆盖该路径，必须验证相关进程和调用已完全移除，才可记录为“随迁移消除”，不能仅因计划替换而关闭。
- **MODEL-PATH-01 / MODEL-STATE-01**：通用目录、共享资源及状态语义继续实施；不再为最终将移除的 IOPaint 路径做长期专属适配，迁移验收仍覆盖旧缓存保护。
- **ENV-01**：扩展范围为消除同一环境先安装旧依赖、再用 `--no-deps` 覆盖版本的冲突根因，统一本地和容器清单。锁定版本或更换安装器不能代替依赖兼容性验证。
- **QUALITY-01 / GEN-01**：将迁移所需的基线与最小生成式试验前移到阶段 A/C，复用其结果；完整质量集和生成式产品功能仍分别验收，不重复开发或自动标记完成。
- **RUNTIME-01**：针对迁移后的执行器测量加载、复用和显存收益，不投入 IOPaint 服务保活重构。
- **DL-01 / DL-02 / DL-03 / MODEL-SAFE-01**：属于通用基础能力，继续适用，移除 IOPaint 不代替这些修复。

## 已有实现与本轮范围

现有 OCR 候选检测、倾斜/增强扫描、手动修正遮罩、局部 LaMa 修复、区域外像素保留和任务恢复机制继续保留。它们已有实现，不能重新列成“尚未开发”；需要改进的是复杂水印的召回、修复质量和上述可靠性边界。

不建议现在整体重写模型管理，不建议一律改为项目自建目录，也不建议直接用生成式模型替换现有修复模式。启动前设置缺省环境变量本身合理；需要修正的是目录优先级、框架版本差异和跨组件解析一致性。

上述顺序优先消除误删、竞态与卡死，然后统一模型管理语义，再推进去水印质量。生成式修复无需等待 RUNTIME-01、FE-PERF-01、ARCH-01 的大范围优化。若部署范围扩大到公网，应另立身份认证与部署安全评审作为上线前置条件。
